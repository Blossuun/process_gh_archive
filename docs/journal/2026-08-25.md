## 의사 결정

### 배치 처리 단위 설정

개인 노트북을 이용한 프로젝트인만큼, 데이터 처리량을 결정하는 사안이 중요함. 주요한 병목은 **16GB**에 해당하는 메모리일 것으로 생각.

이를 고려해서 처리량을 점차 늘리는 테스팅을 통해 적절한 배치량을 설정하도록 할 것임.

로컬에 남은 공간은 500GB 정도이지만 처리전, 처리중, 처리후의 데이터 양이 모두 합쳐 100GB를 넘지 않는 수준에서 데이터 분석을 수행할 수 있도록 조절할 것임.

## 특이 사항

날짜별 데이터를 시험삼아 다운로드하다가, 당연하지만 놓칠 수 있던 사실을 발견함.

데이터의 크기가 날짜별로 편차가 크다. 평일, 주말, 휴일 등의 이유로 큰 것 같음.

날짜별 데이터 크기를 기록했다가, 평일·주말을 제외한 데이터 크기의 차이가 발생하는 이유나 시간의 흐름에 따라 데이터 크기가 어떻게 변했는지 등을 살펴보는 것도 좋을 것 같음.

## 시작 전 최종 구조 결정

기본적인 구조는 bronze와 silver 계층이 임시로 소비되고 삭제되어 로컬에서 차지하는 용량을 최대한 줄이는 구조로 설계.

초기엔 Iceberg 없이 Kafka, Spark의 안정적인 구동과 함께 이를 Airflow로 오케스트레이팅하는 실행 중심의 파이프라인을 생성.

안정적인 실행이 완료된 이후에는 Iceberg를 도입해 중복 처리, 스키마 진화, 롤백 등에 대한 대비를 수행.
